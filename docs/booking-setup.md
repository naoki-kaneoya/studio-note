# Studio note・野田小学校の直接予約

豊中ベンチャーと関連グループのメンバーが、施設を選び、名前・利用日・開始時間・終了時間・メールアドレスを入力して予約する。共有する受付ページは `/book`。
予約可能な場合にGoogleカレンダーへ予定を登録して、予約者を招待する。決済と管理画面はこの初期版に含めていない。

`/book` は予約専用のレイアウトを使用し、施設サイトのメニュー・フッター・固定予約バーを表示しない。共有URLはそのまま維持し、Google Apps Script・カレンダー・Vercelの接続設定も引き続き利用する。

## 今回の初期値

- 予約対象はStudio note（庄内）と野田小学校。施設ごとに既存の共通Googleカレンダーを利用する。別施設同士は同じ時間にも予約できる。
- 庄内は既存案内に合わせ10:00〜20:00。野田小学校は既存の閉館案内に合わせ2026年12月28日まで。閉館日は庄内には適用しない。
- 同じ日の開始・終了時間を分単位、日本時間で指定する。日をまたぐ利用は受け付けない。
- 予約は送信時の空き確認後に即時確定。管理者による承認は不要。
- ログイン・合言葉・メンバー在籍確認は行わない。予約URLを共有して利用する。
- 作成するGoogleカレンダーの予定は「公開」・「予定あり」とし、外部予約サービスからの参照に対応する。
- 変更とキャンセルは管理者がGoogleカレンダーで行う。招待を辞退しただけでは、施設の予約は取り消されない。

閉館日や利用対象の運用が異なる場合は、公開前に予約ルールを変更する。

## 構成

予約サイトをVercelなどに公開し、利用者は各自のスマホ・PCのブラウザーからアクセスする。利用者の端末にアプリのインストールや環境変数の設定は不要。

空き表示は Next.jsフォーム → `/api/availability` → Google Apps Script → Google Calendar Freebusy API。
予約送信は Next.jsフォーム → `/api/bookings` → 同じGoogle Apps Script → Google Calendar API。

施設と日付を選ぶと、その施設の共通カレンダーと追加の照合先から予約済み時間を取得する。予定の件名、予約者名、メールアドレスは公開せず、時間帯だけを表示する。
空き時間を選ぶと開始・終了時間に反映され、空き枠内で利用時間を調整できる。1分ごとの自動更新と手動更新に対応する。現在時刻以前、庄内の営業時間外、野田小学校の閉館後は空き枠として表示しない。
開始・終了時間は大きな数字の「時」「分」へ直接入力する。スマホの時間ダイヤルは使用しない。00・15・30・45分のボタンでも選べ、直接入力では1分単位で指定できる。
同日内の予約のため、野田小学校の終了時刻は23:59まで。日をまたぐ予約は受け付けない。
表示後に別の予約が入る場合があるため、送信時に必ず空き状況を再確認する。取得失敗時は空きと判断せず、予約の新規送信を止める。

Google Apps Scriptは、カレンダーの管理者として実行する。`ScriptLock`でこの予約アプリからの処理を直列化し、空き確認から予定の登録までロックを保持する。
Googleカレンダー側に毎回同じ送信IDから算出した予定IDを渡すため、登録後に応答だけ失われても再送で予定や招待を再作成しない。
カレンダーへのアクセスに失敗した場合は、空きと判断せず受付を停止する。

## 1. 重複確認するカレンダーを決める

1. 各施設の、SpaceMarket・Upnowの予約も入る既存の共通カレンダーを利用する。
2. Googleカレンダーの「設定と共有」→「カレンダーの統合」で、庄内と野田小学校それぞれのカレンダーIDを確認する。
3. Google Apps Scriptを作成するアカウントに、両カレンダーの「予定の変更」権限を付与する。
4. 外部サイトの予約が別カレンダーに入る場合は、管理者アカウントから全て参照できるようにする。

**Googleカレンダーにまだ反映されていない外部予約は、このアプリでは検出できない。**
SpaceMarketやUpnowから予定を取り込むだけの連携や、定期的なiCal取り込みには時間差がある。また、Google側の空き確認直後に外部サイトが予約を受け付けることもある。
公開前に、各サイトの実際の同期方向・更新頻度・空き枠の制御方法を確認する。
全チャネルで二重予約を防ぐには、各サイトも同じ予約台帳に基づいて空き枠を閉じる必要がある。手動入力、別のApps Scriptプロジェクト、外部サイトの書き込みは、このアプリのロックには参加しない。

空き状況の確認にはGoogleのFreebusy APIを使う。「空き時間」扱いの予定は予約をブロックしないため、外部サイトからの予定も「予定あり」で登録する。終日の予定も重複確認の対象。

## 2. Google Apps Scriptを設定する

### 接続URLと秘密値はどこにあるか

この2つはGoogleカレンダーが自動で発行する設定ではない。予約用のApps Scriptを設定すると用意できる。

- `GOOGLE_BOOKING_SCRIPT_URL`：既存の予約用プロジェクトがある場合は、[Google Apps Scriptの一覧](https://script.google.com/home)から開き、**デプロイ → デプロイを管理 → ウェブアプリのURL** で確認する。未作成の場合は、以下の手順でWebアプリをデプロイすると発行される。
- `GOOGLE_BOOKING_SECRET`：既存プロジェクトの場合は、**プロジェクトの設定 → スクリプト プロパティ → BOOKING_BACKEND_SECRET** の値を使う。新規接続では十分に長いランダムな秘密値を作り、Apps Scriptの `BOOKING_BACKEND_SECRET` とVercelの `GOOGLE_BOOKING_SECRET` の両方に同じ値を設定する。

今回のクラウド環境では新規接続用の秘密値を `.env.local` に作成済み。値はGitに含めず、チャットにも表示していない。このファイルは利用者のPCに用意するものではなく、管理者が新規接続を設定する際の参照用。既存の接続を使う場合は、既存の秘密値を優先し、動作中の設定を不用意に置き換えない。
Googleへのログインとカレンダーの権限許可は、管理者アカウントで行う。今回の接続は設定済みで、両施設の実カレンダーの空き照会に成功している。Google側の編集画面の操作は管理者が行う。

### 新規プロジェクトの設定

今回の管理者向けには、予約のコード・初期設定・施設ID・作成済みの秘密値をまとめた `google-apps-script/Booking.private.gs` を用意した。
このファイルを使う場合は、Google側の `Code.gs` をその内容で置き換える。別途 `Setup.gs` を追加する必要はない。
庄内と野田小学校の施設IDはユーザー指定のものを設定済み。管理者による初期設定後、実Googleへの参照と本番の予定登録は確認済み。招待メールの到着は別途確認する。
このファイルには秘密値が含まれ、Gitから除外されている。Google側のプロジェクト作成・権限許可・デプロイは、このクラウドから代行できない。

1. 管理者アカウントでGoogle Apps Scriptの新規プロジェクトを作成する。
2. [google-apps-script/Code.gs](../google-apps-script/Code.gs) の内容をプロジェクトの `Code.gs` にコピーする。
3. プロジェクト設定でマニフェスト表示を有効にし、[google-apps-script/appsscript.json](../google-apps-script/appsscript.json) をコピーする。
4. Calendar API v3が「サービス」に表示されることを確認する。標準Google Cloudプロジェクトを指定している場合は、同プロジェクトでもGoogle Calendar APIを有効にする。
5. 初期設定ファイルを追加して実行する。以下の手動設定でも同じ設定を保存できる。

初期設定ファイルを別に追加する場合は、クラウドで用意した `google-apps-script/Setup.private.gs` の内容を、Apps Scriptの新しいスクリプトファイル `Setup.gs` にコピーする。今回は秘密値と2つのカレンダーIDを設定済み。
このファイルには秘密値が含まれるため、Git・チャット・共有ドキュメントへ載せない。再利用用の、秘密値を含まないテンプレートは [Setup.template.gs](../google-apps-script/Setup.template.gs)。

エディタ上部の関数選択で **setupBooking** を選び、**実行** を押す。管理者アカウントで、コードが要求するGoogleカレンダーと外部通信の権限を確認して許可する。
両カレンダーの空き情報と予定APIを参照できることを確認してから、スクリプト プロパティへ設定を保存する。予定や招待は作成しない。予定の書き込み権限をこの参照確認だけでは検証できないため、管理者には両カレンダーの「予定の変更」権限を付与する。
参照に失敗した場合は設定を保存せず、既存設定が異なる場合も上書きしない。成功したら、秘密値を含むGoogle側の `Setup.gs` は削除してよい。保存済みのスクリプト プロパティは保持される。

手動の場合は、プロジェクト設定の「スクリプト プロパティ」に次を設定する。

| プロパティ | 内容 |
| --- | --- |
| `BOOKING_CALENDARS` | 施設ごとの共通カレンダーIDを指定するJSON。例: `{"studio":"studio@group.calendar.google.com","noda":"noda@group.calendar.google.com"}` |
| `BOOKING_BACKEND_SECRET` | 十分に長いランダムな秘密値。Webサイトとバックエンド間だけで使う |
| `CONFLICT_CALENDAR_IDS` | 任意。追加の照合先を施設ごとに指定するJSON。例: `{"studio":["studio-external@group.calendar.google.com"],"noda":["noda-external@group.calendar.google.com"]}`。全予約が既存の共通カレンダーに入る場合は不要 |

選んだ施設の予約先カレンダーは常に重複確認の対象に含む。追加カレンダーを含めて施設ごとに最大50件。追加したカレンダーに閲覧権限がなければ、予約は受け付けない。両施設に同じ予約先IDを設定すると設定未完了となる。
秘密値は共有ドキュメント・Git・チャットに貼らず、設定画面に直接入力する。

6. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」を選択する。
7. 実行ユーザーを **自分**、アクセスできるユーザーを **全員** にして管理者アカウントで権限を許可する。Next.jsサーバーはGoogleへの対話ログインを行わないため、Webアプリへのサーバー間通信を許可し、本文の秘密値で認証する。
8. 発行された `https://script.google.com/macros/s/…/exec` を控える。`/dev` のテストURLは使わない。

Google Workspaceの組織ポリシーで「全員」が許可されない場合、この構成はそのまま使えない。管理者承認または認証付きの別バックエンドが必要になる。
コード変更時は、既存のデプロイを新バージョンに更新する。複数プロジェクトへ複製せず、同じプロジェクトを利用する。

### 公開予定への更新と、登録済み予約の修正

1. 既存のApps Scriptプロジェクトの `Code.gs` を、このリポジトリの [Code.gs](../google-apps-script/Code.gs) で置き換えて保存する。保存済みのスクリプト プロパティと接続URLはそのまま使う。
2. **デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン「新バージョン」→ デプロイ** で、同じWebアプリのコードを更新する。Vercelだけの更新ではGoogle側のコードは更新されない。
3. すでに非公開で登録された予約は、エディタ上部で **publishExistingBookings** を選んで一度実行する。件数が実行ログに出る。

この処理は両施設の、終了していないこの予約アプリの予定だけを公開へ変更する。予定IDと専用の管理情報で識別し、手動予定・外部サービスの予定・終了済み予定を変更しない。日時・招待者・件名を維持し、招待メールは再送しない。公開済みの予定はスキップするため、途中で失敗しても再実行できる。

## 3. Webサイトのサーバー環境変数

公開サイトのホスティング設定に一度だけ登録する。Vercelの場合、対象プロジェクトの **Settings → Environment Variables** を開く。利用者の端末での設定は不要。`NEXT_PUBLIC_` は付けない。

| 変数 | 内容 |
| --- | --- |
| `GOOGLE_BOOKING_SCRIPT_URL` | 前手順のWebアプリの `/exec` URL |
| `GOOGLE_BOOKING_SECRET` | Apps Scriptの `BOOKING_BACKEND_SECRET` と同じ秘密値 |

クラウド環境では、秘密値の設定に環境設定画面を使う。`GOOGLE_BOOKING_SECRET`はWebサイトとApps Script間の通信認証用で、予約者には入力させない。
Codexのクラウド環境設定は開発・検証用であり、公開先のVercel設定には自動転記されない。VercelではProductionに登録し、必要に応じてPreviewにも設定する。変更後は再デプロイする。
環境設定の下書きに `BOOKING_ACCESS_CODE` が残っている場合は不要なので削除する。予約受付はこの変数に依存しない。

サーバーから `script.google.com` と、Apps Scriptの応答リダイレクト先 `script.googleusercontent.com` へのHTTPS通信を許可する。
Googleカレンダーへの通信と権限認証はApps Script側で行うため、このWebサイトにGoogleのOAuthクライアントシークレットやユーザーのパスワードを設定する必要はない。
招待は `sendUpdates=all` を指定してGoogleカレンダーから送る。Resendの設定はこの予約機能には不要。
予定の保存成功は、招待メールの到着や参加者の承諾を保証しない。

## 4. 確認してから受付を開始する

自動テストはNode.js 24で `npm test`。実際のGoogleへの通信はモックで置き換え、重複、同時処理中、再送、キャンセル、アクセス失敗を検証する。
実カレンダーでの招待到着とApps Scriptの権限は、接続設定後に別途確認する。

2026年10月5日、接続URLをクラウドの `.env.local` に設定し、管理者がカレンダーの「予定の変更と共有」権限を付与して `setupBooking` の成功ログを確認した。その後、Webサイトと同じ秘密値を使った実通信で、庄内・野田それぞれの空き照会が `OK` になることを確認した。初期設定前の `UNAVAILABLE` は解消済み。
権限の共有と、スクリプト プロパティの保存は別の操作。新規設定で空き照会が `UNAVAILABLE` になる場合は、同じApps Scriptプロジェクトの `setupBooking` の成功ログを確認する。コードを変更していなければ、プロパティの保存だけでWebアプリを再デプロイする必要はない。
本番で予約予定がGoogleカレンダーへ登録されることは確認済み。招待メールの到着と外部予約サービスへの同期は別途確認する。空き表示の接続確認では、予約登録も招待送信も行っていない。
スマホ幅の実画面でも、両施設の空き時間と予約済み時間が表示され、空き枠を押すと開始・終了時間に反映されることを確認済み。施設を切り替えると前の選択時間が消える。検証中は予約POSTを遮断し、実予約を送っていない。

このクラウドでは既存のHTTPSプロキシをNode.js 24のfetchでも使うため、開発サーバーの起動時に `NODE_USE_ENV_PROXY=1` を指定する。Google接続を持つ検証用サーバーは `--hostname 127.0.0.1` でローカルに限定する。一般利用者向けの公開はVercelなどの公開先で行う。

本番前はテスト用カレンダーと、管理者が管理するテスト用メールアドレスを使う。

- 初回の予約でGoogleカレンダーに予定が1件入り、指定アドレスへ招待が届く。
- `/book` で施設と日付を選ぶと、既存予定の前後の空き時間が表示される。空き時間を押すと開始・終了時間に反映される。
- 施設・日付を切り替えた際、前の施設・日付の応答で空き表示が上書きされない。
- カレンダーの参照に失敗すると空き確認エラーになり、新規予約は送信できない。
- 予約結果が不明な通信エラーでは「予約結果を再確認する」を押す。入力内容と送信IDが固定され、登録済みの予約で空き枠が消えても同じ予約の結果を確認できる。
- 一部でも時間が重なる予約、終日の既存予定は拒否される。
- 前の予約の終了時刻と次の予約の開始時刻が同じ場合は受付できる。準備・片付け時間の余白はこの初期版では自動追加しない。
- 同じ内容の通信再送で予定と招待が増えない。同時の別送信で重なる予約が2件作られない。
- SpaceMarket・Upnowの予約が、参照するカレンダーに「予定あり」で反映される。
- 庄内と野田小学校で、同じ時間帯に1件ずつ予約できる。庄内の予約は野田小学校の空き枠を消費しない。
- 野田小学校の閉館後の日付、過去の開始時刻、庄内の営業時間外では予約を受け付けない。
- 管理者が予定をキャンセル・削除すると空き枠が戻る。ゲストが招待を辞退するだけでは空き枠にならない。

テスト用予定は確認後に管理者が削除する。実メールの送信や本番カレンダーの更新は、管理者が確認できる状況で実施する。

## 公開して共有するURL

公開先はVercel。[docs/deploy-vercel.md](deploy-vercel.md) に従い、既存の本番プロジェクトへGoogle接続の設定と今回のコードを反映する。予約サイトはVercelで稼働し、Googleカレンダーの操作は設定済みApps Scriptを経由する。iMacをサーバーとして稼働させる必要はない。
現在の共有用予約URLは `https://studio-note-steel.vercel.app/book`。
Codexクラウド環境をセットアップしただけでは、一般利用者が使える公開URLは発行されない。

- `/book`: 両施設を選べる予約フォーム。
- `/book?resource=studio`: 庄内を最初に選択したフォーム。
- `/book?resource=noda`: 野田小学校を最初に選択したフォーム。
- `/noda/book`: 野田小学校を選択した共通フォームへ転送する。
